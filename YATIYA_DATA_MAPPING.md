# Yatiya Couture Data Mapping

This document maps the existing frontend mock architecture (localStorage and contextual data) to the Prisma schema for Phase 8B integration.

| Frontend Data Concept | Database Model | Important Fields | Transformation Required | Notes |
|---|---|---|---|---|
| **Frontend Product** (`MockProduct`) | `Product` | `id, name, slug, description, categoryId` | Direct Mapping | Core product details. |
| **Frontend Product Pricing** (`MockProduct`) | `Product` | `price`, `salePrice` | `number` to `Decimal` | Discounts will be dynamically calculated or mapped from `discount` fields. |
| **Frontend Product Colors/Sizes** | `ProductVariant` | `sku`, `size`, `color`, `priceOverride` | Convert arrays (`sizes[]`, `colors[]`) into distinct rows in `ProductVariant` | Cross product variants needed (e.g., Size M + Color Gold). |
| **Frontend Product Images** | `ProductImage` | `url`, `alt`, `sortOrder` | Extract from `images[]` array into relational rows. | One-to-many relationship mapping. |
| **Frontend Category** (`MockCategory`) | `Category` | `id`, `name`, `slug`, `description`, `image` | Direct Mapping | Supports hierarchies via `parentId`. |
| **Frontend Collection** (`MockCollection`) | `Collection` & `ProductCollection` | `id`, `name`, `slug` | Direct Mapping | Many-to-many join tables needed. |
| **CartContext** (`localStorage: cart`) | `Cart` & `CartItem` | `customerProfileId`, `sessionId`, `items` | The frontend session state will need to persist items to `CartItem` linked to a database `Cart`. | `priceSnapshot` to capture current price at insertion. |
| **WishlistContext** (`localStorage: wishlist`) | `Wishlist` & `WishlistItem` | `productId`, `addedAt` | Arrays of IDs on frontend will move to relational mapping rows. | Requires linking to `CustomerProfile`. |
| **CustomerContext** (`localStorage: yatiya_customer`) | `User` & `CustomerProfile` | `email`, `firstName`, `lastName`, `phone` | Map authentication logic to `User`, contextual profile metadata to `CustomerProfile`. | Will likely require a provider like NextAuth.js. |
| **Address List** (`localStorage: yatiya_addresses`)| `Address` | `addressLine1`, `city`, `state`, `pincode`, `type` | Arrays will become independent `Address` records related to `CustomerProfile`. | Requires boolean mapping for `isDefault`. |
| **Orders** (`localStorage: yatiya_orders`) | `Order` & `OrderItem` | `subtotal`, `total`, `status`, `shippingAddressId` | `number` to `Decimal`, status string mapping to `OrderStatus` enum. | `OrderItem` will capture price/name snapshots to avoid history corruption. |
| **Admin Orders View** | `Order` & `Shipment` | `orderNumber`, `trackingUrl` | Requires robust relations to `Address` for shipping vs billing views. | Admin sees joined views of multiple models. |
| **Mock Inventory** | `Inventory` | `variantId`, `quantity` | Will move from a flat `stockStatus` attribute on the Product to an atomic quantity linked to `ProductVariant`. | The most complex logical jump for checkout flows. |
| **Coupons** | `Coupon` & `CouponUsage` | `code`, `discountValue`, `minOrderAmount` | Direct Mapping | Logic will move from client-side calculations to server-side validation. |

### Migration Notes:
- **Keys / IDs**: Frontend is using string identifiers like `prod-1`. During migration, these should transition to UUIDs or CUIDs generated by PostgreSQL/Prisma.
- **Numbers to Decimals**: All currency operations will shift from JavaScript primitives to `Prisma.Decimal` instances.
- **Relationships**: The existing frontend assumes heavily denormalized data (e.g. `product.categoryId`). Prisma enforces strict relational referential integrity.
